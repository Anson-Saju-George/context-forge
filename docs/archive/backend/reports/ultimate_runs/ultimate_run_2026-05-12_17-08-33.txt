## 📚 03_attention_is_all_you_need.pdf  
**Title**: "Attention Is All You Need" (Vaswani et al., 2017)

### 🔎 Problem Solved  
- **Problem**: Prior NLP models (e.g., RNNs, LSTMs) suffer from **long-range dependency issues**, **slow training**, and **limited parallelization**.  
- **Solution**: Introduces **Transformer architecture**, which replaces recurrence with **self-attention mechanisms**, enabling **parallelization**, **long-range context modeling**, and **scalable training**.

### 🔍 Research vs. Implementation  
- **Research-focused**  
- This is a foundational research paper that proposes a new architecture for sequence modeling.

### 🔑 Key Architectures, Algorithms, Mechanisms, Workflows  
| Component | Details |
|--------|--------|
| **Self-Attention Mechanism** | Computes attention weights between every pair of tokens in a sequence using query, key, value vectors. Enables modeling of long-range dependencies. |
| **Multi-Head Attention** | Splits attention into multiple heads, each focusing on different subspaces (e.g., syntax, semantics). Improves model expressiveness. |
| **Encoder-Decoder Architecture** | Uses stacked encoder layers (for input processing) and decoder layers (for output generation). |
| **Positional Encoding** | Adds positional information to input tokens (since attention is invariant to order). Uses sinusoidal functions. |
| **Layer Normalization** | Applied after each sub-layer to stabilize training. |
| **Feed-Forward Networks** | Applied after attention layers, with two linear layers and ReLU activation. |

### 🎯 Core Technical Concepts Introduced  
- **Self-attention**: Allows each token to attend to all others in a sequence.  
- **Multi-head attention**: Enables parallel attention across multiple subspaces.  
- **Transformer block**: A single unit combining attention and feed-forward networks.  
- **Positional encoding**: Injects sequence order into models without recurrence.  
- **Parallelization**: Enables training on full sequences in parallel (vs. RNNs' sequential nature).

> ✅ **Evidence**: Table 4 shows the Transformer outperforms prior models (e.g., Dyer et al., 2016) on constituency parsing, even without task-specific tuning — proving generalization capability.

## 📚 01_retrieval-augmented_generation_for_knowledge-intensive_nlp_tasks.pdf  
**Title**: Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

### 🔎 Problem Solved  
- **Problem**: Foundation models (like Llama 2) lack **up-to-date knowledge** and **factuality**. They may hallucinate or generate incorrect information.  
- **Solution**: Introduce **Retrieval-Augmented Generation (RAG)** — a mechanism that **retrieves external documents** during generation and **uses them to augment responses**.

### 🔍 Research vs. Implementation  
- **Implementation-focused**  
- This document details **RAG workflow**, **indexing**, **search**, and **deployment** — it is a **practical, production-ready pipeline**.

### 🔑 Key Architectures, Algorithms, Mechanisms, Workflows  
| Component | Details |
|--------|--------|
| **RAG Pipeline** | 1. Document collection → 2. Embedding → 3. Indexing → 4. Query → 5. Retrieve top-k documents → 6. Generate response using retrieved content. |
| **Document Indexing** | Stores document vectors (embeddings) in a vector database (e.g., FAISS). |
